# Política de segurança

## Relatos de vulnerabilidade

Não inclua no conteúdo público de issues, pull requests ou discussões: senhas, tokens, chaves, amostras de dados de clientes, endereços internos ou detalhes exploráveis de uma falha ainda não tratada.

Para problemas no próprio conteúdo do projeto SENTINELA, contate o mantenedor por um canal privado disponível no perfil do GitHub. Se um canal privado não estiver disponível, compartilhe apenas uma descrição geral, sem provas de conceito sensíveis.

## Uso autorizado

Execute testes de segurança somente em sistemas sob sua administração ou com autorização explícita, respeitando o escopo acordado. A Skill deve solicitar permissão antes de realizar testes ativos ou alterações.
